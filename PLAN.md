# Saguki: Plan

A flashcard app in the style of Anki, built for language learning (Japanese, Traditional Chinese, and more). It has native Windows and Android clients, works offline first, and syncs automatically through your VPS.

---

## 1. Stack

| Layer | Choice | Why |
|---|---|---|
| Clients (Windows + Android) | **Flutter** (one codebase) | Compiles to native code for both targets. One UI codebase means the PC and phone look and behave the same. |
| Local DB | **SQLite via `drift`** | Typed queries and reactive streams that update the UI automatically. Works on Windows and Android. Reviews keep working with no network. |
| Scheduler | **FSRS** (`fsrs` pub package, MIT) | Modern replacement for Anki's SM-2 with fewer reviews for the same retention. Runs on the client. |
| Backend | **Dart (`shelf` + `postgres`)**, single container | Same language as the app, so models and DTOs live in one shared package. The backend only does auth and sync. |
| Server DB | **PostgreSQL 16** | Source of truth for sync and backups. |
| Reverse proxy | **Caddy** | Automatic HTTPS from a 3-line config. |
| Deploy | **Docker Compose** on the VPS: `caddy` + `api` + `postgres` + nightly `pg_dump` | One `docker compose up -d`. |
| TTS (pronunciation audio) | `flutter_tts`: OS voices (Windows OneCore ja-JP / zh-TW, Android Google TTS) | No audio files to store or sync. |

**Sync decision: hand-rolled delta sync instead of PowerSync or ElectricSQL.** PowerSync supports Flutter on Windows and Android. Self-hosting it, though, adds another service, separate bucket storage (MongoDB by default), Postgres logical replication, JWT plumbing, *and* you still need your own write API. For one user with a few devices, a push/pull endpoint is about 200 lines and has nothing extra to run. Upgrade path: if real-time collaboration or many users ever matter, move to PowerSync.

### Sync design (as built in P1)
- Every synced client row has `id` (UUIDv7, generated on the client), `modified_at` (client clock, epoch **ms**), `deleted` (soft delete) and `dirty` (not pushed yet).
- **Server storage is opaque:** one Postgres table `sync_rows(tbl, id, modified_at, deleted, data jsonb, version)`. The server never needs a migration when the app schema changes. Clients do all scheduling and stats.
- **One endpoint, `POST /sync {cursor, changes}`:** the server applies the pushed rows (a row only replaces the stored one if its `modified_at` is newer), then returns every row with `version > cursor`. Writers are serialized with an advisory lock so a pull never skips a row.
- **On the client:** an incoming row is skipped if the local copy is dirty and at least as new. Pushed rows are marked clean only if they weren't edited while the request was in flight.
- `review_logs` are append-only. An undo writes a tombstone, because the log may already be synced. Card scheduling state is last-write-wins: if you review the same card offline on both devices, the later review wins.
- **Auth:** a single user. The password lives in the server's `.env`, and each device gets its own long-lived random token, stored as a hash in `devices`. To revoke a device: `DELETE FROM devices WHERE name = …`.
- **Auto-sync triggers:** app start, app resume, 5 s after any local change (debounced), and every 60 s while the app is in the foreground.
- **Known limits (marked `ponytail:` in the code):**
  - Pulls aren't paged; that's fine up to roughly 50k rows.
  - The token is a plain file in app-private storage.
  - A wrong password only costs a fixed 1 s delay; there's no per-IP lockout.
  - Clock skew between devices can make an older edit win.
- Tests:
  - `server/test/smoke.sh` covers auth and last-write-wins.
  - `app/test/sync_e2e_test.dart` runs two devices through a real server.

## 2. Data model (client SQLite; the server stores the same rows as JSONB)

```
devices      id, name, token_hash, last_seen                   -- server only
decks        id, user_id, name, language, emoji, color, description,
             new_per_day, review_limit, desired_retention, …sync cols
notes        id, deck_id, language?, term, pronunciation, meaning_en,
             explanation, example, example_translation, tags text[], …sync cols
cards        id, note_id, direction('fwd'|'rev'),
             due, stability, difficulty, state, reps, lapses, last_review, …sync cols
review_logs  id, card_id, rating(1-4), reviewed_at, duration_ms,
             state_before, elapsed_days, scheduled_days      -- append-only
```
Notes (the content) are kept separate from cards (the scheduling), as in Anki. This allows an optional reverse card (English → foreign word) per note. Changing this split later is painful, so it goes in from day one. Only forward cards are generated by default.

Language codes are BCP‑47: `ja`, `zh-Hant`, `zh-Hans`, `ko`, …

## 3. Language detection & quick switching

**Detection runs per field and is pure Unicode-range logic, with no ML:**
1. Kana (U+3040–30FF) present → `ja`
2. Hangul → `ko`
3. Han characters only → look up the characters in a small JP-shinjitai vs Traditional table (学/學, 国/國, 気/氣, 図/圖 …). If that doesn't decide it, fall back to the deck's language.
4. Latin → `en` (the meaning/explanation fields)

**What the detected language drives:**
- **Font locale.** This is critical. Because of Han unification, the same codepoint (直, 骨, 角) has different glyphs in JP and TC. Every CJK `Text` gets `locale:` set, so Japanese never renders with Chinese glyphs or the other way round.
- **Pronunciation format:** furigana above the term for `ja`, zhuyin or pinyin (your choice per deck) for `zh-Hant`.
- **TTS voice:** ja-JP or zh-TW, with speed set per language in the profile.
- **Quick switch:** a language pill bar at the top of Home and Stats (`All · 日本語 · 繁體中文`). It filters decks, the due count, the heatmap, and stats. It is one tap, and the app remembers your last choice.

**Phase 4 bonus: dictionary autofill.** Type a term and the term, pronunciation, and English get filled from **JMdict** (JP) and **CC‑CEDICT** (zh), both free (CC BY-SA). They are loaded into Postgres on the server. This needs a connection; offline you type the fields by hand.

**As built in P4:**
- Ruby over the term: `pron.dart` aligns furigana to kanji runs (the kana in the word anchor the split) and accepts Anki's `食[た]べ 物[もの]` syntax. Zhuyin and pinyin go per character when the syllable count matches. Otherwise the whole reading sits over the whole word.
- `/dict` on the server: JMdict and CC-CEDICT are downloaded into the `dict` table on first start, which takes about 15 s and about 525k rows. A failed download retries on the next restart.
- The editor autofills empty pronunciation and English 400 ms after you stop typing, and lists other matches to tap.
- zh-Hant pronunciation follows the Profile setting (zhuyin or pinyin), and zh-Hans uses pinyin.
- The pill filter is a synced pref (`langFilter`) shared by Today and Stats.

## 4. Import / export
| Format | Import | Export |
|---|---|---|
| CSV / TSV (column mapping UI) | ✅ | ✅ |
| `.sgki` (zip of JSON, full fidelity incl. scheduling + review history) | ✅ | ✅ |
| Anki `.apkg` | ✅ notes + fields mapped to our fields; review history converted | ❌ (skip, add if you actually need to go back to Anki) |

**As built in P2** (`app/lib/transfer.dart`):
- **Anki package formats:** `.apkg` and `.colpkg` both work, in the legacy layout and the modern zstd-compressed `anki21b` one.
- **Field mapping:** Anki fields are matched by name, for example Expression/Reading/Meaning/Sentence/Sentence-English. A note type nobody recognises falls back to field 1 as the word and field 2 as the meaning.
- **Scheduling:** if a card already has FSRS memory state in Anki, it's reused. Otherwise its SM-2 interval and ease are converted. Review history carries over.
- **Re-importing:** IDs come from Anki's, so importing the same deck again updates it instead of duplicating it.
- **CSV:** columns are matched by header name (Word/English/Reading/…). Without a recognised header, columns are read in the export's order.
- **Skipped for now:** media (images and audio), and Anki's extra card templates such as reverse cards. Only template 1 is imported. There's also no column-mapping screen yet.

## 5. Stats (Stats screen)
- **Heatmap:** a year of daily reviews in GitHub style, on a lavender ramp. Tap a day to see its counts.
- **Streaks:** current and best, with a “studied today” check.
- **Cards learned:** new → learning → young → mature (interval ≥ 21 d), shown as a stacked bar.
- **True retention:** % of reviews answered correctly, today / 7 d / 30 d, compared with your target.
- **Reviews per day** (bar) and **time studied** (minutes per day, avg seconds per card)
- **Forecast:** due cards for the next 30 days
- **Answer buttons:** distribution of Again / Hard / Good / Easy
- **Best hour:** retention by hour of day ("you remember best at 9 pm")
- **Top lists:** hardest cards (leeches, lapses ≥ 8), most-reviewed decks, recently mastered words
- **Per-language** breakdown (driven by the pill bar)
- **Milestones:** 100 / 500 / 1 000 / 5 000 cards learned, streak badges on the profile

All of these are SQL over `review_logs` on the client, so they work offline.

## 6. Profile (customizable)

## 7. Design

### Research takeaways
- **Review screen = nearly nothing.** One prompt, large type, controls always in the same position. When the layout stays fixed, you build muscle memory over hundreds of cards.
- **Active recall:** reveal with Space or tap, then rate with **4 buttons that show the next interval** (`<10m · 2d · 4d · 9d`). Keys **1–4**, Space reveals, **Z** undoes.
- **Android:** swipe to rate, with color verdicts and haptics on commit, *plus* buttons as an accessibility fallback.
- **Progress without noise:** a thin progress bar at the top and a "cards left" count, nothing else.
- **Dark mode:** no pure black. Use a **tinted near-black base**, show elevation by making surfaces *lighter* rather than adding shadows, use a **desaturated pastel accent**, and use the accent sparingly. Body text must be ≥ 4.5:1 (WCAG AA).

### Fonts: ⚠️ SF Pro licensing
Apple's SF license only allows use **on Apple platforms**, so it can't legally ship in a Windows or Android app.
**Default:** **Inter** (the closest open match to SF: same proportions, tabular numerals, an optical "Display" cut for big titles), with SF's iOS type scale.
The font family is a single token in the theme, so if you own the SF files and accept the risk for personal sideloaded builds, swapping is one line.
CJK: bundle **Noto Sans JP + Noto Sans TC** (with locale switching, see §3), because Windows' default CJK fallback is inconsistent.

**Type scale (SF/iOS):** Large Title 34 bold · Title1 28 · Title2 22 · Title3 20 · Headline 17 semibold · Body 17 · Callout 16 · Subhead 15 · Footnote 13 · Caption 12. On the card, the foreign term is 56 (desktop 72) and the pronunciation is 20.

### Color tokens (dark only)
| Token | Hex | Use |
|---|---|---|
| `bg` | `#0E0D12` | app background (purple-tinted near black) |
| `surface1` | `#16151C` | cards, nav |
| `surface2` | `#1E1C26` | raised: sheets, inputs |
| `surface3` | `#272433` | hover / pressed |
| `border` | `#2E2B3A` | hairlines |
| `text` | `#ECEAF2` | primary (≈16:1) |
| `text2` | `#A9A5B8` | secondary (≈8:1) |
| `text3` | `#6F6B80` | tertiary, large or decorative only (≈3.8:1) |
| `accent` | `#B9A7FF` | **lavender**: primary buttons, focus, active nav (≈9:1 on bg) |
| `accentContainer` | `#2C2547` | selected chips, heatmap mid |
| `onAccent` | `#17132A` | text on lavender buttons |
| `again / hard / good / easy` | `#FF8A94 / #F2C078 / #86D9A8 / #8EC9FF` | rating buttons (desaturated) |

Heatmap ramp: `surface2 → #3A3160 → #5B4C99 → #8B78D9 → #B9A7FF`.
Shapes: 14 px radius on cards and 10 px on buttons (the iOS continuous-corner feel), 8 pt spacing grid, motion 200 ms ease-out, and a card flip that cross-fades rather than doing a 3D spin.

### Visual direction: **A · Quiet** (chosen)
iOS-native and nearly empty. Content sits directly on `bg`, with no card container on the review screen. Hierarchy comes from type size and weight, not boxes. Lavender appears only on the meaning, the progress bar, active nav, and the single primary button per screen. Rating buttons are plain colored text with the interval underneath, always in the same position. Hairline (`border`) dividers separate the back of the card into meaning, explanation, and example. The rest of the app follows suit: grouped list sections on `surface1` (iOS Settings style), large titles that collapse on scroll, and no decorative tiles.

### Screens & layout
Adaptive: a **sidebar** at window width ≥ 840 px (desktop), a **bottom nav** on the phone.
1. **Today:** greeting, due ring (new / learning / review), streak, language pills, deck list with due counts, big "Study" button
2. **Review:** full-bleed and distraction-free (see the research takeaways)
3. **Decks / Browse:** search all cards, filter by deck, language, tag, or state, bulk edit
4. **Card editor:** fields with a live language-detect chip, a TTS preview, and dictionary autofill (Phase 4)
5. **Stats:** §5
6. **Profile / Settings:** §6, plus Import/Export

Desktop extras: keyboard-first everywhere (`/` search, `N` new card, `S` study).

## 9. Phases
| # | Deliverable | Done when |
|---|---|---|
| **P0** | Flutter app, theme tokens, drift schema, deck and card CRUD, FSRS review screen, TTS | You can study a deck offline on PC and on the phone |
| **P1** | Server, Postgres schema, login + device tokens, push/pull sync, docker compose on the VPS | Add a card on the PC and it appears on the phone within a minute |
| **P2** | Import/export: CSV, `.sgki`, `.apkg` | Your existing Anki decks come over with their history |
| **P3** | Stats screen + profile | Heatmap and the stats in §5 render from real data |
| **P4** | Language detection everywhere, furigana/zhuyin ruby, pill switcher, JMdict/CC-CEDICT autofill | Typing 勉強 autofills べんきょう + "study" |
| **P5** | Release: signed APK (`--split-per-abi`), Windows MSIX/installer, daily review reminder notification | Installed on both devices |

**Skipped on purpose:** iOS, web client, shared or public decks, AI-generated cards, image occlusion, a sync WebSocket, Anki export. Each one is easy to add later if you want it.
